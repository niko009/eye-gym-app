# Eye Gym — Growth & Distribution Roadmap

Created: 2026-08-23
Status: active strategy
Scope: Eye Gym first; small browser games may be used as an acquisition/retention channel when they reinforce the product.

## North Star

Turn Eye Gym from a working product into a product people discover, try, return to, recommend, and eventually pay for — without medical claims or growth mechanics that conflict with the product's wellbeing focus.

The order matters:

**Measure → improve activation → create retention → build organic acquisition → distribute → experiment with paid acquisition → monetize → scale what works.**

Do not spend meaningful money on promotion before analytics and activation/retention measurement are working.

## Primary audience

Initial segments to validate rather than target everyone at once:

1. Developers and other people spending many hours at a computer.
2. Office/remote workers with long daily screen time.
3. Students and knowledge workers.
4. Parents looking for healthier screen-break habits for children — only where the existing child-safe experience is appropriate.

Start with developers/office workers because the problem is frequent, easy to communicate, and these users can use the web/PWA product immediately.

## Growth funnel

Every growth task should improve one of these stages:

1. **Discovery** — user sees Eye Gym in search, social content, a community, recommendation, article, game, or directory.
2. **Visit** — user lands on a page matching their intent.
3. **Activation** — user starts and completes a first useful action: exercise/workout or screen-break cycle.
4. **Return** — user comes back on another day.
5. **Habit** — Eye Gym becomes part of the work/screen routine.
6. **Referral** — user shares or recommends it.
7. **Revenue** — a useful paid tier/product is introduced only after usage proves what users value.

## Phase 0 — Baseline and measurement

Goal: know what is happening before trying to grow traffic.

- Define analytics events for landing-page view, workout start/completion, timer start/completion, PWA install, notification opt-in, return session, signup/login, share/referral, and game entry/completion.
- Create one simple weekly dashboard.
- Record baseline traffic, acquisition source, activation rate, D1/D7/D30 retention, workouts per active user, timer completions, PWA installs and returning-user share.
- Add UTM conventions for every external link/campaign.
- Verify privacy/cookie requirements for the chosen analytics implementation.
- Establish uptime/performance/error monitoring so promotion never sends traffic to a broken experience.

Exit condition: we can identify where users come from and whether they reach the first useful result.

## Phase 1 — Product readiness for growth

Goal: make a first visit understandable and useful in under a minute.

- Sharpen homepage promise: what Eye Gym is, who it is for, and what the user can do immediately.
- One obvious primary CTA such as starting a short routine.
- Add a zero-registration first-use path where possible.
- Build a short onboarding path that explains timer, routines, progress and PWA installation without a long tutorial.
- Make sharing easy after a positive completion moment, but never pressure the user.
- Improve mobile/PWA install experience.
- Verify RU/RO/EN landing copy and metadata.
- Add trust/about/evidence pages and preserve the existing non-medical product boundary.
- Run Lighthouse/Core Web Vitals/accessibility checks and fix high-impact issues.

Exit condition: first-time users can understand, start and complete the core experience with minimal friction.

## Phase 2 — Retention and habit loop

Goal: give users a reason to return before buying more traffic.

- Personal routine presets based on available time and screen-work pattern.
- Continue gentle reminders/notifications controlled by the user.
- Weekly progress summary: sessions, breaks, streak-like consistency without punishment for missed days.
- Useful milestones/badges already aligned with child-safe gamification principles.
- Add a lightweight “today” state so returning users instantly know what to do.
- Test reminder timing and onboarding variants.
- Interview or collect feedback from early repeat users and people who tried once but did not return.

Key decision metric: D7 retention and repeat weekly use must improve before scaling acquisition.

## Phase 3 — SEO engine

Goal: create compounding free discovery.

Build search pages around actual user intent, not mass AI-generated articles.

Content clusters:

- eye break timer / 20-20-20 timer;
- screen break reminder;
- eye exercises for computer users (careful evidence wording);
- digital eye strain / computer-work habits;
- blinking and screen breaks;
- workspace ergonomics related to screen use;
- short interactive routines;
- multilingual RU/RO/EN versions where search demand justifies them.

Actions:

- Technical SEO: indexability, canonical URLs, sitemap, robots, structured data where appropriate, metadata, Open Graph, performance and internal linking.
- Create focused landing pages for major intents instead of sending every query to the homepage.
- Publish a small number of genuinely useful evergreen guides/tools.
- Interlink each article/tool with an immediate Eye Gym action.
- Build free interactive tools that can rank and earn links: 20-20-20 timer, break planner, screen-time routine builder, printable checklist.
- Review Search Console monthly and expand pages that already receive impressions.

## Phase 4 — Content and community distribution

Goal: manually find the first hundreds/thousands of relevant users and learn what messaging works.

Primary content formats:

- 15–30 second demonstrations of an Eye Gym routine;
- “work with me” screen-break clips;
- simple developer/office-worker screen habit tips;
- before/after workflow stories rather than medical outcome claims;
- development/build-in-public posts;
- small visual games/challenges that lead naturally into Eye Gym.

Channels to test one at a time:

- YouTube Shorts;
- TikTok;
- Instagram Reels;
- Reddit communities where self-promotion is permitted;
- developer communities and relevant forums;
- Product Hunt / Indie Hackers / Hacker News only when the launch/story genuinely fits;
- Moldova/Romania/Russian-speaking communities for the existing language advantage.

Rule: participate usefully; do not spam links. Track every channel with UTM tags and compare activation/retention, not raw clicks.

## Phase 5 — Games as a growth channel

Goal: use small games to make Eye Gym more discoverable and shareable without turning it into an unrelated game portal.

Games should be short, web-first, replayable and connected to visual attention/screen-break behavior where reasonable.

Possible formats:

- target tracking;
- peripheral-attention challenge;
- focus-switching challenge;
- visual search/pattern game;
- calm 20-second distance-break companion;
- daily challenge with a shareable result.

Each game needs:

- instant play without signup;
- mobile support;
- a shareable result/card;
- analytics for game → core Eye Gym conversion;
- a natural CTA into a routine/timer;
- no unsupported claim that the game improves eyesight or treats a condition.

If games bring traffic but users never enter the core product, treat them as a separate entertainment experiment rather than assuming they grow Eye Gym.

## Phase 6 — Referral and partnerships

Goal: make distribution less dependent on the founder posting constantly.

- Simple referral/share links with attribution.
- Shareable completion/progress cards that avoid sensitive personal data.
- Outreach to small productivity/newsletter creators before large influencers.
- Partnerships with developer communities, coworking spaces, schools/teachers only where positioning is appropriate, and workplace-wellness communities.
- Offer a free team challenge or screen-break week as a B2B acquisition experiment.
- Create a compact press/creator kit: screenshots, description, demo video, founder story and safe claims.

## Phase 7 — Monetization experiments

Do not put the useful basic habit behind a hard paywall prematurely.

Potential model to validate:

**Free**
- core routines;
- basic timer/reminders;
- basic progress;
- selected games.

**Pro / Supporter**
- deeper personalization;
- richer history/statistics;
- additional themes/routines;
- cross-device/account features;
- advanced reminder schedules;
- optional premium game/content packs.

**Teams later**
- team screen-break challenges;
- privacy-conscious aggregate participation;
- organization configuration.

Pricing should be tested only after qualitative interviews and usage data show what repeat users value.

## Phase 8 — Paid acquisition

Goal: buy traffic only after the funnel has evidence of retention.

- Start with very small experiments.
- Test high-intent search ads before broad display traffic.
- Retarget only if privacy/consent setup supports it and the economics make sense.
- Measure cost per activated user and retained user, not CPC alone.
- Stop channels that produce cheap visits but weak activation/retention.

No serious ad budget until organic/manual acquisition shows that users return.

## 90-day execution structure

### Weeks 1–2 — Instrument and prepare

Analytics, funnel events, Search Console, performance/errors, baseline metrics, homepage/CTA/onboarding audit.

### Weeks 3–4 — Activation

Improve first-run experience, landing proposition, PWA install path, sharing, trust/evidence content. Recruit the first small feedback group.

### Month 2 — Organic acquisition

Launch the first SEO landing pages/tools, publish consistently in 1–2 chosen content channels, begin community distribution, collect qualitative feedback and measure source quality.

### Month 3 — Retention + experiments

Improve the returning-user loop, launch 1–2 small shareable game experiments, test referral mechanics and 2–3 small partnerships. Decide which acquisition channel deserves the next 90 days.

## Weekly operating rhythm

Every week:

1. Review traffic → activation → retention by source.
2. Identify the single biggest funnel bottleneck.
3. Ship one meaningful improvement or experiment.
4. Publish/distribute several pieces derived from the product rather than creating unrelated content.
5. Talk to at least one real user whenever possible.
6. Record experiment, result and decision.

## Metrics hierarchy

North-star candidate: **weekly active users who complete at least one useful Eye Gym action.**

Supporting metrics:

- unique visitors;
- organic search impressions/clicks;
- visit → first-action activation rate;
- workout/timer completion rate;
- D1/D7/D30 retention;
- WAU/MAU;
- PWA install rate;
- notification opt-in rate;
- sessions/actions per active user;
- referral/share rate;
- game → core-product conversion;
- later: free → paid conversion, MRR, churn, CAC and LTV.

Vanity metrics such as views/followers should never be the primary success criterion.

## Prioritization rule

Use this order when choosing work:

1. Broken core experience.
2. Missing measurement.
3. Activation blockers.
4. Retention blockers.
5. Organic acquisition assets.
6. Distribution experiments.
7. Referral/partnership loops.
8. Monetization.
9. Paid scaling.

New feature ideas should not displace growth work unless they clearly improve activation, retention, referral or revenue.

## Experiment log

For every growth experiment record:

- hypothesis;
- target audience;
- channel/change;
- metric to move;
- start/end date;
- result;
- keep / iterate / stop decision.

Create a separate experiment-log document when active growth experiments begin.

## Immediate next step

Before expanding this roadmap into dozens of tasks, perform a **Growth Baseline Audit** of the current production site and repository. That audit should establish current analytics, SEO/indexing, landing-page clarity, activation path, retention mechanisms, PWA state, performance, shareability and existing acquisition assets. Then convert Phase 0 and Phase 1 into concrete GitHub tasks in priority order.
