# Eye Gym Web/PWA и Telegram Mini App — техническое задание v1.1

## Цель

Создать расширенную веб-версию Android-приложения Eye Gym для расслабления глаз, которая работает как обычный сайт, устанавливаемая PWA и Telegram Mini App. Все каналы используют одну React-кодовую базу, общий backend, базу данных, упражнения и локализацию. Приложение должно работать без регистрации и без сети там, где это поддерживает среда запуска, поддерживать независимые Google- и Telegram-профили, синхронизацию статистики и голосовое сопровождение на русском, румынском и английском языках.

Продукт не является медицинским средством, не обещает лечение или улучшение зрения и позиционируется как набор упражнений для расслабления глаз.

## Аудитория и локализация

- География: весь мир.
- Язык по умолчанию: русский.
- Языки интерфейса, упражнений и аудио: RU, RO, EN.
- Интерфейс mobile-first с полноценной адаптацией для desktop.
- Telegram Mini App поддерживается во всех официальных клиентах Telegram с актуальной поддержкой Mini Apps; вне Telegram приложение сохраняет полноценный browser/PWA-режим.
- Поддерживаются светлая, тёмная и системная темы.
- Визуальная основа: Android-приложение, Nunito, бирюзово-зелёная палитра.
- Целевой уровень доступности: WCAG 2.1 AA.

## Комплексы и тренировки

Переносятся все комплексы Android с совпадающими упражнениями, длительностью и паузами:

1. Quick Start.
2. Work Break.
3. Full Recovery.
4. Stress Relief.
5. Focus Marathon.
6. Malyshev Method.

Случайный выбор упражнений сохраняется там, где он используется в Android. Состав фиксируется при запуске сессии. Пользователь может поставить тренировку на паузу, продолжить, пропустить упражнение, вернуться назад или выйти. В статистику попадают только полностью завершённые комплексы. Незавершённые сессии не сохраняются.

## Голосовое сопровождение

Используются заранее сгенерированные аудиофайлы RU/RO/EN. Для каждого упражнения создаётся временной сценарий: название, инструкция, команда начала, промежуточные команды, завершение и отдых. Аудио синхронизируется с таймером, паузой, возвратом и пропуском.

Выбранный языковой пакет автоматически загружается для офлайн-работы. Другие пакеты пользователь может скачать отдельно. Тексты и аудиофайлы готовятся отдельным этапом и утверждаются владельцем.

## Авторизация и синхронизация

- Гостевой режим предоставляет всю функциональность.
- Google OAuth используется для синхронизации между устройствами.
- В Telegram Mini App пользователь может войти через подтверждённые Telegram `initData` без Google OAuth.
- Google- и Telegram-профили являются независимыми пользователями. Они не связываются и не объединяют историю автоматически, даже если принадлежат одному человеку.
- Автоматическое сопоставление аккаунтов по email, имени, телефону или другим профильным данным запрещено.
- Связывание и объединение Google- и Telegram-профилей в v1 не входит.
- Сохраняются доступные профильные поля провайдера, настройки и статистика. Для Google это могут быть email и имя; для Telegram email не ожидается.
- После первого входа локальная статистика объединяется с выбранным Google- или Telegram-профилем идемпотентно. Одна гостевая запись не должна автоматически переноситься сразу в оба профиля.
- Сессия хранится в Secure, HttpOnly, SameSite cookie.
- Самостоятельное удаление и экспорт данных в v1 не входят; запрос можно отправить на контактный email.

## Telegram Mini App

- Telegram является дополнительным каналом текущего Web/PWA-проекта, а не отдельной кодовой базой.
- Mini App открывается из меню проекта-бота или по прямой ссылке Telegram и использует production HTTPS URL сайта.
- Клиент подключает официальный Telegram Web App SDK, вызывает `ready()` после загрузки критического интерфейса и использует доступные методы с проверкой версии клиента.
- Интерфейс учитывает Telegram theme parameters, изменение темы, viewport, safe area и content safe area.
- Навигация интегрируется с Telegram Back Button; для подходящих действий используется Haptic Feedback. Интерфейс не должен дублировать системные элементы Telegram без необходимости.
- В обычном браузере отсутствие `window.Telegram.WebApp` не считается ошибкой: Telegram-функции отключаются, а приложение продолжает работать как сайт/PWA.
- Для входа клиент отправляет на API исходную строку `Telegram.WebApp.initData`. API проверяет подпись с помощью токена бота и срок действия `auth_date` до использования Telegram user ID.
- `initDataUnsafe`, query-параметры и переданный клиентом объект пользователя не могут использоваться как доказательство личности.
- Токен Telegram-бота хранится только на сервере и не попадает в frontend bundle, логи или публичные конфигурационные endpoints.

## Статистика

Сохраняются завершённые тренировки: ID, комплекс, фактический состав, время начала и окончания, продолжительность и язык. Интерфейс показывает количество тренировок, общее время, текущую и лучшую серии, последнюю тренировку, историю, статистику комплексов, любимый комплекс, календарь и графики по дням, неделям и месяцам.

Гость хранит данные в IndexedDB. Авторизованный пользователь дополнительно синхронизирует их с сервером. Офлайн-записи отправляются после восстановления сети. Серия продолжается при наличии хотя бы одной полной тренировки в локальный календарный день. Доступен полный сброс прогресса с подтверждением.

- Service worker и офлайн app shell.
- Кеш интерфейса, переводов, анимаций и загруженных аудиопакетов.

## Напоминания

Пользователь задаёт несколько ежедневных времён. Часовой пояс определяется автоматически. Дни недели и snooze не требуются. В browser/PWA Web Push работает через VAPID, service worker и бесплатный self-hosted worker. В Telegram напоминания отправляет проект-бот только после явного согласия пользователя и возможности написать ему. Гостевые web-push подписки привязаны к анонимному ID установки, а после входа — к аккаунту. Telegram chat ID хранится отдельно и используется только для включённых Telegram-напоминаний.

## Self-hosted архитектура

Production запускается на Linux через Docker Compose и не привязан к провайдеру:

- `web`: React/TypeScript/Vite и статический web server;
- `api`: Node.js/TypeScript API;
- `worker`: расписания, Web Push и отправка Telegram-сообщений;
- `postgres`: основная база;
- `proxy`: Caddy и HTTPS;
- `backup`: регулярный `pg_dump`.

Обязательны healthchecks, именованные volumes, миграции, backup/restore, `.env.example`, отсутствие секретов в Git и возможность переноса на другой сервер.

## Данные

Базовые таблицы: `users`, `auth_identities`, `auth_sessions`, `user_settings`, `workout_history`, `reminder_schedules`, `push_subscriptions`, `telegram_deliveries`, `guest_installations`, `schema_migrations`.

`auth_identities` хранит пару `provider + provider_subject`, уникальную для `google` и `telegram`, и ссылается на `users`. В v1 одна identity создаёт отдельного пользователя; механизм объединения нескольких identities с одним пользователем не предоставляется. Telegram chat ID и состояние согласия на сообщения хранятся отдельно от публичных данных профиля.

## CI/CD

GitHub Actions запускает lint, typecheck и тесты, собирает образы, публикует их в GHCR, подключается к серверу по SSH, создаёт backup, выполняет миграции и запускает `docker compose up --wait`. После деплоя проверяется health endpoint; при ошибке используется предыдущий SHA образов.

## Критерии приёмки

- Все 6 комплексов совпадают с Android.
- RU/RO/EN полностью локализованы.
- Таймер, пауза, возврат и пропуск корректны.
- Голосовой сценарий синхронизирован с тренировкой.
- Учитываются только завершённые тренировки.
- Гостевые данные идемпотентно переносятся после первого входа в выбранный Google- или Telegram-профиль.
- Telegram Mini App открывается через бота, корректно применяет тему и навигацию Telegram и остаётся работоспособным при изменении viewport.
- Telegram-вход принимается только после серверной проверки подписи и срока действия `initData`.
- Google- и Telegram-профили одного человека сохраняются как независимые пользователи и не обмениваются статистикой.
- Гостевые данные могут быть идемпотентно перенесены в выбранный Telegram-профиль.
- Авторизованные данные синхронизируются между устройствами.
- Установленная PWA и выбранный аудиопакет работают офлайн.
- Push приходит по заданному времени при поддержке платформы.
- GA4 не загружается до согласия.
- Docker Compose разворачивается на чистом Linux-сервере, а backup восстанавливается по инструкции.
